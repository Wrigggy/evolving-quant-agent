# QFBench Offline Verifier Cache Canary

> Date: 2026-07-24
> QFBench commit: `024921eb507fcc0c4ffe3e0a96802724be1ae84a`
> Scope: local dependency-cache and lock-command validation only

## Method

The exact dependency declarations were extracted from the five pinned official `tests/test.sh` files. Using uv 0.9.5 and Python 3.11.14, each distinct `uvx` declaration was first prewarmed, then rerun with all of the following fixed:

- `UV_OFFLINE=1`
- `UV_CACHE_DIR`
- `UV_TOOL_DIR`
- `UV_TOOL_BIN_DIR`

The generated template lock command was also executed offline and wrote an installed-package inventory. The option parity task invokes the base-image Python directly, so its template uses `pip freeze` instead of `uvx`.

## Results

| Official tasks | Dependency declaration | Offline result |
|---|---|---|
| `historical-var-data-prep`, `momentum-backtest` | pytest 8.4.1, CTRF 0.3.5, NumPy, pandas | PASS; NumPy 2.4.6, pandas 3.0.5 |
| `fx-forward-cross-rate` | pytest 8.4.1, CTRF 0.3.5, NumPy 2.2.3, pandas 2.2.3 | PASS |
| `evt-pot-var` | preceding pinned set plus SciPy 1.15.2 | PASS |
| `option-put-call-parity-forward-audit` | direct Python | Not applicable to uv cache; `pip freeze` lock generated by template |

All three offline `uvx ... pytest --version` checks exited 0 with `pytest 8.4.1`. The generated dependency-lock command also exited 0 and captured direct plus transitive package versions.

## Interpretation and Limits

This proves local offline cache reuse and command construction; it does not execute QFBench assertions or establish Linux/E2B parity, seed reward, held-out reward, or evolution improvement. The successful checks ran outside the restricted macOS filesystem sandbox because uv panicked while reading the host system-configuration API inside it; `UV_OFFLINE=1` remained set. The two official unpinned requirements can resolve differently on a later build, so a pilot must retain and reuse its E2B build ID and `/opt/qea/verifier-requirements.lock`.
