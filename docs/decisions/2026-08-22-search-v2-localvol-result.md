# Search-v2 local-vol result

Date: 2026-08-22

## Decision

Retain Search-v2 as a positive search-mechanism result and retain its frozen
candidate as a target-positive but non-promotable candidate.

The result closes the immediate question of whether the Quant Research State
representation can change a real Evolver decision and produce an official
gain. It does not yet close property-wise protection safety, Main-0 lifecycle
automation, planned-task coverage, or sealed benchmark performance.

## Matched proposal setup

The strong generic and quant-state-v2 Evolvers started from the same
Quant-H0, runtime candidate, Worker trajectory, official score, answer-rich
optimization diagnostic, component history, model route, mutation surface,
and proposal limits. A direct comparison of their authorized evidence trees
found only the arm contract to differ. Both Evolvers could edit the full
harness and the Worker remained answer-blind.

The generic Evolver used nine completed requests, cost $0.046818996, and
returned a calibrated `ABSTAIN`: the static evidence retained two competing
explanations and it did not justify an intervention.

Quant-state-v2 used 18 completed requests, cost $0.067801596, and returned an
admitted `ACT`. It selected:

- primary relation: `maturity_propagation_terminal_completeness`;
- residual-risk relation: `local_vol_surface_terminal_coverage`; and
- component locus: `systemprompt`.

It retained the prior calibration-admissibility and artifact-consistency
discipline, then added a pre-delivery requirement that maturity-indexed
outputs cover every selected maturity, define the terminal derivative, and
contain no missing numeric cells. The candidate was a prompt-only refinement;
no task-specific expected value or checker was added.

## Official target and repeat

On the first normal-budget `dupire-local-vol` comparison, fresh Quant-H0
scored 65/68 with reward 0. The frozen Search-v2 candidate scored 68/68 with
reward 1.

On the independent repeat, a new Quant-H0 Worker scored 66/68 with reward 0.
The same frozen candidate again scored 68/68 with reward 1.

Both candidate Workers produced the predicted observations before official
verification: finite positive terminal values, a defined one-sided terminal
difference, all selected maturities represented in the delivered surface, and
no NaN or blank numeric cells. This is a repeated official binary gain aligned
with the predeclared quantitative relations.

## Matched second task

On `localvol-barrier`, fresh Quant-H0 and the frozen candidate both scored
38/39 with reward 0.96. The candidate did execute the declared relation-aware
workflow: it represented all five target expiries at all seven target strikes,
checked positive finite local volatility, scanned the written CSV artifacts
for missing cells, and documented artifact self-consistency.

The aggregate tie is not property-wise Pareto safety. Quant-H0 failed
`barrier_outputs_reasonable`, while the candidate passed that property and
instead failed `vanilla_mc_close_to_surface`. The intervention therefore
changed the matched task in a mechanism-consistent way but exchanged one
failed property for another. Under the property-level protection gate, it is
not promoted.

The retained verdict is:

- target: `TASK_HELPFUL`, independently repeated;
- matched task: declared relation executed and aggregate score preserved;
- protection: property-set regression;
- lifecycle decision: `ROLLBACK` / archive, not promotion; and
- reusable scope: not yet established.

## What the result supports

The canary supports the following bounded claim:

> With the same runtime experience, quant-state-v2 selected a primary and an
> independently supported residual relation, justified a minimal harness
> refinement that the matched generic Evolver abstained from, and produced two
> independent official binary improvements whose artifacts realized the
> predicted relation corrections.

It does not establish that Quant Research State search generally outperforms
generic harness evolution. It also does not establish safe cross-task reuse:
the matched task executed the relation-aware workflow and preserved aggregate
score, but its failed-property identity changed.

## Cost and experimental integrity

The full Search-v2 path used 228 completed model requests, 13,880,354 tokens,
and $0.515488768 in provider cost. It comprised two Evolver proposal sessions,
one admitted candidate, six normal-budget Worker sessions, and six official
verifier executions. There were no rate-limited retries, replacement attempts,
or unreconciled attempts. The campaign stayed below its $0.75 stage-start cap.

The five retained run IDs are recorded in
`data/breadth/QSTATE_SEARCH_V2_RESULT.json`; mirrored evidence lives under
`results/bc-mirror/`.

## Pre-main consequence

Search-v2 satisfies the pre-main domain-observation gate through a repeatable
binary gain and actual relation execution on a matched second task. Main-0 is
still not started.

Before Main-0:

1. freeze a small source-level applicability table for the proposed Main-0
   tasks, with at least two public quantitative relation families;
2. retain the matched-contract audit above as the S2 control record; and
3. implement the thin JSON candidate-lifecycle controller that consumes the
   existing proposal, target, repeat, and protection reports and performs
   promotion or rollback exactly once on resume.

Main-0 should use this Search-v2 candidate as a real rollback path. A separate
already measured protection-safe candidate can exercise the promotion path;
Main-0 does not need to pay to rediscover Search-v2.
