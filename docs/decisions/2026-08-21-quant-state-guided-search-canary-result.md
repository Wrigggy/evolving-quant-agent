# Quant-state-guided search canary result

Date: 2026-08-21

## Outcome

The Quant Research State Card is now an operational search treatment rather
than a naming layer. Under matched Quant-H0, evidence, model, and evaluation
budgets, both quant-state Evolvers issued admitted `ACT` decisions, selected
different quantitative relations, and changed different harness surfaces.
Fresh Workers improved official property counts over concurrent Quant-H0 in
both task families.

The strongest retained result is the holdings family. Its quant-state
candidate scored 50/51 twice on `13f-amendment-aware-crowding`, compared with
concurrent Quant-H0 samples of 48/51 and 37/51. The unchanged candidate then
kept `brinson-sector-attribution` at 42/42. The candidate component was called
on protection, but correctly returned a grounded schema-mismatch skip; the
Worker preserved the full result through its ordinary workflow. This is
repeated target property gain plus safe protection, not execution of the same
reconciliation relation on a second task.

The local-vol family did not pass its repeat gate. On the first normal run,
the generic candidate reached 68/68 and the quant-state candidate 67/68,
compared with Quant-H0 at 66/68. On the independent repeat, generic fell to
67/68 and the quant-state Worker timed out without a scorable artifact. No
local-vol protection run was dispatched.

The canary therefore supports quant-state-guided mechanism localization and
one repeated property-level improvement. It does not yet support a stable
binary gain, matched-relation transfer, benchmark-level improvement, or a
Main-0 go decision.

## Matched setup

The comparison used two mechanism families:

- information/effective/derived-state reconciliation:
  `13f-amendment-aware-crowding` as target and
  `brinson-sector-attribution` as protection; and
- estimation/calibration reconciliation: `dupire-local-vol` as target and
  `localvol-barrier` as protection.

For each family, generic and quant-state Evolvers received the same corrected
task evidence, retained component catalog and runtime history, model route,
reasoning effort, Worker, mutation surface, and proposal/evaluation budget.
The treatment was the operational State Card plus coordinate-guided retrieval
and routing. The generic arm retained strong layered causal diagnosis and full
access to the same evidence; it was not weakened into a task-only baseline.
The Worker remained answer-blind in both arms.

The valid campaign used 515 completed model requests, 26,669,461 tokens, and
$2.087186840. Earlier runs that exposed a redundant State Card evidence-access
gate and one stale remote deployment are retained as setup-invalid attempts
and excluded from these totals and scientific comparisons.

## Autonomous interventions

For holdings, the quant-state Evolver selected
`final_state_reconciliation`, routed primarily to an executable tool, and
created `reconcile_portfolio_deliverables` with prompt, tool-description, and
agent-configuration support. Its short selected probe produced an artifact and
scored 48/51.

For local-vol, the quant-state Evolver selected
`calibration_parameter_admissibility` and changed the system prompt. Its short
probe exhausted eight turns without an artifact. Under normal budget the
candidate nevertheless fixed the selected positive-SVI admissibility failure,
showing that the selected relation was locally meaningful, but it left a
separate forward-variance relation unresolved.

The generic local-vol Evolver built a broader executable
`validate_surface_model` component. It initially covered both residuals and
reached 68/68, but the binary result did not repeat. This is useful evidence
against treating one positive Worker sample as a stable candidate.

| holdings target, first | 48/51 | 49/51 | 50/51 |

All scored target arms had binary reward zero except the first generic
local-vol run. Both protection Quant-H0 and quant-state arms had reward one.
The generic holdings candidate regressed severely on protection and is
rejected. The quant-state holdings target remained one property short of
binary reward.

## What the State Card changed

This experiment gives a narrower and more useful conclusion than “finance
wording helps.” The State Card changed:

1. which runtime evidence was retrieved;
2. which relation was selected as the intervention target;
3. which harness component was mutated; and
4. which observation was predicted before Worker execution.

The two families produced different relations and component loci, so the
treatment did not collapse to one prompt template. In holdings it yielded a
repeatable final-state reconciliation workflow. In local-vol it correctly
isolated one calibration admissibility defect, but one selected relation was
too narrow to cover the orthogonal residual and did not produce a stable
Worker completion path.

The next search revision should therefore allow one primary relation and at
most one evidence-supported residual-risk relation. This is not an exhaustive
finance failure taxonomy. It is a small competing-relation budget intended to
avoid declaring the candidate complete after repairing only the first visible
quantitative inconsistency.

## Lineage and scale interpretation

Lineage remains implementation bookkeeping: it records the current parent,
candidate change, predicted relation transition, observed Worker result,
promotion or rollback, and resume point. The protection regression shows why
that bookkeeping matters, but lineage itself is not the method contribution.

Main-0 is not ready to run at broad scale yet. The canary closes the search-
treatment wiring gap and provides one repeated target property gain with safe
protection. It leaves three concrete gates:

1. obtain one repeatable binary improvement or a second repeatable property
   gain under a different mechanism family;
2. execute the selected relation on a genuinely matched second task, rather
   than only calling a component that then skips; and
3. make long-tail monitoring distinguish active numerical computation from a
   genuinely stalled Worker.

The fixed file-progress watchdog marked both long local-vol Workers as stalled
while one was using roughly two CPU cores for numerical fitting. Neither run
needed a restart. The repeat ultimately timed out, so active computation and
successful completion must remain separate observations.

The immediate engineering repair makes the host-side no-file-progress window
configurable and changes its QFBench default from 20 to 60 minutes. This is a
bounded response to the observed false alert; it is not a new scheduler or a
claim that CPU activity implies useful progress.
