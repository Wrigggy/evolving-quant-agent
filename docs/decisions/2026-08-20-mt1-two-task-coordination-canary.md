# MT-1 two-task coordination canary

Date: 2026-08-20

## Why this follows AP-3 r5

AP-3 r5 established the complete bounded feedback loop from Quant-H0, but the
selected passive skill activated without causing an edit. The remaining issue
is choosing a component and Worker experiment that discriminate a concrete
failure mechanism efficiently.

MT-1 is not the deferred progressive scheduler. It gives one Evolver two to
four answer-free Quant Research Trajectories, requires an explicit shared-
mechanism assessment, and permits exactly one Worker probe in the round. Other
tasks remain contrast trajectories until a target improvement exists.

## Initial pair

The initial pair stays within the QFBench rates domain because the retained
failures share a concrete quantitative object rather than only a broad Research
State:

- target `zero-coupon-bootstrapping`: retained 1/6, with bootstrap and curve-
  consistency failures;
- protection `swap-curve-bootstrap-ois`: retained 17/19, with dual-curve
  bootstrap and repricing failures.

Both require constructing discounting objects from quoted instruments and
reconciling them by repricing. T26 remains a cross-benchmark reserve: it also
contains multi-stage numerical conventions, but current evidence does not show
the same curve-construction failure, so it must not be described as matched
transfer evidence.

## Coordination contract

The Evolver must first state whether the tasks share one concrete mechanism,
quantitative object, or executable invariant. A common label such as
`quantitative_representation` is insufficient. ACT requires exactly one
`probe_task_key`, one reusable candidate, and one observable action target:
an artifact edit, a validator finding acted upon, or a supported skip.

Only the selected target is evaluated during search. The protection task runs
only after an official target improvement. A non-match, unsupported mechanism,
no-action probe, or target non-improvement ends the branch without evaluating
every task.

The existing cross-benchmark experience-card adapter remains the evidence
surface, and benchmark-specific Worker/verifier paths remain unchanged. The new
code adds only a coordinated view and contract; actual paid dispatch is a
separate gate after no-model preflight.
